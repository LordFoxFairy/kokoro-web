# PRD-002: Kokoro 整体管理后台壳层

## 1. 产品定义

`Kokoro Admin` 是整个 Kokoro 系统的统一管理后台，不是“运营后台”，也不是只服务 IAM 的
单用途控制台。当前版本只展示已经完整实现并可执行的 IAM 管理能力；后续子仓完成自己的
PRD、技术方案、实现和验收后，再通过稳定模块描述注册到同一后台。

## 2. 用户与目标

主要用户是平台管理员、系统管理员和安全管理员。首屏必须让用户明确自己进入的是
`Kokoro 管理后台`，并能快速完成用户、会话、组织、访问控制和安全审计工作。

目标：

- 统一产品身份、导航和页面布局，避免每个后端能力重复实现后台壳层。
- 保留高密度、可扫描、适合重复操作的企业管理界面。
- 只展示真实可用模块，不出现“即将上线”菜单、空壳页或不可执行按钮。
- 默认并固定使用浅色主题；本阶段不提供深色主题切换。
- IAM 继续通过 ConnectRPC 和 `KOKORO_IAM_BASE_URL` 接入，不改变业务权威边界。

## 3. 信息架构

### 3.1 全局壳层

- 左侧浅色导航：Kokoro 品牌、当前产品“管理后台”、分组菜单、折叠控制。
- 顶部浅色全局栏：当前模块、语言、管理员身份和退出命令。
- 主工作区：页面标题、简短业务说明、紧凑工具区、表格或详情内容。
- 移动端：侧栏收起为标准菜单入口，主操作和正文不得横向溢出。

### 3.2 当前可执行导航

| 分组 | 页面 |
| --- | --- |
| 总览 | 系统概览 |
| 身份管理 | 用户、会话、组织 |
| 权限与安全 | 访问控制、安全审计 |

导航由 Admin 自己的模块注册表管理。IAM 模块提供页面描述，但不得拥有平台品牌、全局顶栏
或未来模块的占位入口。

## 4. 视觉方向

参考用户提供界面的结构和密度，不复制其品牌、数据或具体卡片：

- 页面画布使用冷灰白，侧栏和顶栏使用白色或极浅蓝灰。
- 主色使用清晰蓝色；状态使用绿色、琥珀色和红色，不使用单一色系覆盖全部界面。
- 活动菜单使用浅蓝底和蓝色文字；普通菜单保持深灰文字。
- 圆角控制在 6-8px；阴影只用于顶栏、浮层和确有边界需要的重复项目。
- 列表业务默认使用表格；卡片只用于独立指标或重复实体，不嵌套卡片。
- 筛选、批量动作和页面命令保持紧凑，避免营销式大标题和装饰性区域。
- 桌面主密度针对 1440px 及以上优化，同时覆盖 1024px 和 360px。

## 5. 文案规则

必须删除产品级“运营”“Operations Console”“IAM Operations Console”定位。

| 场景 | 中文 | 英文 |
| --- | --- | --- |
| 产品名 | Kokoro 管理后台 | Kokoro Admin Console |
| 登录标题 | 登录管理后台 | Sign in to Kokoro Admin |
| 当前管理员 | 当前管理员 | Current administrator |
| 总览 | 系统概览 | System overview |

IAM 可以出现在具体模块、服务状态和业务说明中，但不能替代平台产品名。

## 6. 非目标

- 不新增未实现的后端模块、聚合 API、通用代理或中央数据库。
- 不改变 IAM 数据模型、RPC、Auth.js、软删除、幂等或权限业务逻辑。
- 不引入主题市场、可配置布局、拖拽看板或低代码页面生成器。
- 不处理部署、TLS、网关、证书或运维拓扑。

## 7. 验收标准

1. 登录页、HTML metadata、全局品牌和导航均使用整体管理后台定位。
2. 默认中文与英文均不再出现产品级“运营控制台”文案。
3. 侧栏、顶栏、工作区和所有 Ant Design 组件均为浅色主题。
4. 当前只展示 6 个真实可用入口；所有入口可到达并完成现有 IAM 业务。
5. 1440x1000、1024x768、360x800 下无文字截断、无控件重叠、无页面级横向溢出。
6. 键盘焦点、语义导航、按钮标签和表格区域保持可访问。
7. 组件、单元、契约和集成测试全部通过；浏览器最终验收在 Codex 内置浏览器逐步执行。
8. 测试报告按认证、导航、用户、会话、组织、权限、安全、响应式分类，记录本地/UTC 时间与截图。
