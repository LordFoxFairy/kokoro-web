## 最新决策

1. Admin Web 以 `satnaing/shadcn-admin@e16c87f213a5ba5e45964e9b67c792105ec74d26`
   为实际视觉、布局和组件组织底座，并保留 MIT 声明。
2. shadcn/ui 原语只采用官方 CLI 与 Registry；上游组合模式适配到 Next.js，不恢复 Vite、
   TanStack Router、Clerk、Tasks/Chats/Apps 示例导航或 Demo 数据。
3. 技术栈固定为 Next.js 16 App Router、React 19、Tailwind CSS 4、Radix UI、Lucide、
   TanStack Table、React Hook Form、Zod 与 Auth.js。
4. Admin Web 与 IAM 保持清晰边界，只通过版本化 API 契约协作。
5. 当前阶段不修改 IAM 仓库，不在前端复制 IAM 的租户隔离、授权闭包或生命周期规则。
6. fixture 只服务 Admin 独立研发与可见验证，不代表 generated ConnectRPC 或真实 IAM 验收。
7. 不引入 Ant Design、ProComponents、Clerk、Vite、Docker、旧 Admin 兼容层或 Demo 业务。

## 新任务执行顺序

### 1. 启动与可见审查

```bash
cd /Users/nako/WebstormProjects/github/thefoxfairy/Kokoro/kokoro-web
pnpm --dir apps/admin exec next dev --webpack -H 127.0.0.1 -p 3100
```

在内置浏览器打开 `http://127.0.0.1:3100/`，逐页截图检查桌面和移动端。优先修复：

- 样式缺失、字体闪动、布局跳动和横向溢出
- Sidebar 展开/折叠、移动 Sheet、Command 搜索、主题切换
- 表格搜索、排序、列显隐、空结果和详情跳转
- 权限诊断允许、拒绝、未知场景和字段校验

### 2. Auth.js

```bash
pnpm --filter @kokoro/admin add next-auth@beta
```

实现：

- `auth.ts` 与 App Router Route Handler
- 账号密码登录 provider，调用 Admin/IAM 版本化认证契约
- Auth.js Session 到现有 `SessionView` 的单一映射
- Console layout 路由保护、安全 callback、退出和 Session 失效
- development/test 开发账号工具；production 完全关闭
- 邮箱注册保留为后续契约能力，不在 Admin 前端伪造邮件链路

不要把密码校验、账号状态或权限规则复制到前端。

### 3. 管理 mutations

先更新 API 契约与 generated fixture，再实现：

- 用户创建/编辑/启停/删除恢复/角色分配
- Organization 与 Site 创建/编辑/成员管理
- 角色创建、权限树授权、删除恢复与使用情况
- 会话撤销与结果回读
- 审计详情 Drawer 与 mutation 审计回读

统一使用官方 shadcn Dialog/Sheet、RHF/Zod 和结构化错误码；按钮不得保留无行为状态。

### 4. generated ConnectRPC

- 只使用生成类型与生成客户端
- fixture 与真实 RPC 使用同一 generated contract
- Admin BFF 保持 server-only，不向浏览器暴露 IAM 地址或凭据
- 环境地址来自 `.env.local`，不写死部署 URL

### 5. 最终验收

完成组件、契约、权限、响应式、性能和首屏无闪动测试，并在可见内置浏览器执行两轮完整 E2E。
证据必须包含逐步截图、RPC、SQL 结果核验、审计、日志、分类状态和执行时间。所有项目通过前保持
`NOT_READY`，不得标记 `ACCEPTED`。
